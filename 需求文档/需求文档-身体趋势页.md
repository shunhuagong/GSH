# 需求文档：身体趋势页（体重 / 体脂率 / 骨骼肌）

> 类型：**数据 + 功能混合型**。数据层（新增字段 + 迁移）先写死，功能层（趋势页交互）再展开。
> 参照图：体脂秤 App「身体趋势」页（三 tab 指标切换 + 折线 + 参考虚线 + 左右翻页箭头）。
> 执行前先读 AGENTS.md 与《需求文档-训练进步看板.md》第七节（历史锁定、体重删除等未提交变更登记）。

## 一、背景与现状

- 「我」页原有的体重卡（当前值/较上次变化/近90天折线/记录弹窗）**已删除**；但数据层 `weight_logs` 表、DAO、迁移完整保留（`date / weightKg / createdAt`，Room v9）。
- 设置页 profile 体重仍在——它是**营养目标的计算依据**（体重 × 系数），不属于本需求、不可动。
- 痛点：体重只有"设一个数算目标"这一处用途，历史记录无入口记录、无地方看趋势；体脂率、骨骼肌两个指标完全没有记录能力，但这两项只有体脂秤能测、App 必须有地方存和看。

## 二、数据层（★ 混合型需求的核心节，先于功能定死）

1. **表结构**：复用 `weight_logs` 表，新增两列（Room v9 → v10，加法迁移）：
   - `bodyFat REAL`（体脂率，单位 %，允许 null）
   - `muscleKg REAL`（骨骼肌重量，单位 kg，允许 null）
   - 迁移语句**逐字照抄**：

```kotlin
private val MIGRATION_9_10 = object : Migration(9, 10) {
    override fun migrate(db: SupportSQLiteDatabase) {
        db.execSQL("ALTER TABLE `weight_logs` ADD COLUMN `bodyFat` REAL")
        db.execSQL("ALTER TABLE `weight_logs` ADD COLUMN `muscleKg` REAL")
    }
}
```

2. **空值语义（关键口径，防 0.0 事故）**：没测的指标**不存数**（null），**禁止存 0**——0 会让折线掉到地板。存量老记录两列自动为 null。
3. **记录入口**：新建"身体记录"弹窗（体重 kg / 体脂率 % / 骨骼肌 kg 三个输入框，体重必填、其余可选）——放身体趋势页内（见功能层）；一天一条，同日重复保存 = 覆盖更新当日记录。
4. **历史锁定适配**：身体记录是"当天的新写入"，天然在 7 天锁内；但若做"翻历史日期补录身体数据"，必须过 `isDateLocked()` 闸（**本版不做补录**，只允许记录当天）。

## 三、目标交互（功能层）

**一句话**：新增"身体趋势"二级页，三个指标 tab 切换，各自画近 90 天折线，页内可记录当天身体数据。

1. **入口**：「我」页原体重卡位置放一个入口卡「📊 身体趋势」（点开进二级页，路由方式同设置页/看板页）。**不动底部导航。**
2. **tab 结构**：体重 / 体脂率 / 骨骼肌 三个胶囊 tab，选中主题色白字、未选中浅灰底黑字；默认选中"体重"；切 tab 只切折线数据源，**页面不重载**。
3. **每条折线**：
   - 复用现有 Canvas 折线画法（同「我」页训练看板/体重旧折线），**不引入图表库**；
   - 数据点 = 该指标有记录（非 null）的日期；点上方标注数值（如 `63.8`）；
   - 主题色描点 + 渐变填充；纵轴范围按该指标数据自适应（留 10% 余量）；
   - 无记录的指标 tab：显示灰字空态"还没有体脂率记录，点下方记录"（不画空线）。
4. **记录弹窗**（页右下「＋ 记录」按钮）：三个输入框按数据层口径（体重必填、体脂/骨骼肌可选留空）；保存后折线立即更新。
5. **时间窗口翻页**：图表右上左右箭头，切换 近90天 / 更早90天 窗口（同参照图）；越界（无更早数据）时对应箭头置灰。
6. **参考线（二期，本版不做）**：体重目标范围虚线——设置页加"目标体重范围"后再画。本版明确不做。

## 四、约束

1. **不碰饮食、训练模块**；不改底部导航；不加账号/云同步。
2. **设置页 profile 体重勿动**（营养目标计算依据）；身体趋势的体重记录与 profile 体重是**两回事**，本版不做"记录体重时同步 profile"（如要同步另行拍板）。
3. 迁移仅限第二节那两条 ALTER，**逐字照抄**；装机后验证：老体重历史记录完好、App 正常启动（迁移 v9→v10 是本需求唯一高风险点）。
4. 折线 Canvas 手绘，不引入图表库。
5. 身体数据只做记录与展示，**不做健康评价/建议**（体脂多少算好由用户自己判断；AI 分析接入是另一个需求）。
6. 本版不做历史日期补录身体数据（7 天锁定外的路径直接不存在）。
