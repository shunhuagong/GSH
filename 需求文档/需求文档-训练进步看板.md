## 一、现状快照（全部已落地，勿重做）

App 版本 v2.2（code 13），Room **version 9**，训练模块当前能力：

| 能力 | 现状 |
|---|---|
| 逐条训练记录 | `training_entries(date, exerciseId, weightKg?, reps?, durationSec?, createdAt)`，按天存储 |
| 录入交互 | 选动作 → 回训练页出卡片 → **行内三框 kg/次/秒**（72/56/64dp、48dp 高、无提示词、单位 suffix）→ ✓ 保存；✕ 取消丢弃 |
| 合法输入三选一 | kg+次 ｜ 只次 ｜ 只秒；其余组合 ✓ 置灰 |

| 组号 | 显示层计算（当天+动作+入库顺序），删组自动补位；「第 N 组」浅灰徽章 |
| 上次带过 | 待填行自动预填**该日期之前**最近一次的第 N 组（不足带上一组），`lastSetsOfBefore` 严格 `<` |
| 日期解耦 | 显示/录入/标记训练日均跟随 `selectedDate`；翻历史日期可补录那天 |
| 动作分类 | `muscleGroup` 逗号分隔多标签（腿/背/胸/肩/臂/腹，"核心"已同步改"腹"）；看板/选择器按标签过滤 |
| recordType | **只剩看板口径**：新建一律 -1，首次保存按所填 settle，启动 `backfillRecordTypes` 幂等回填；已有 0/1/2 不回滚 |
| 看板 | 「我」页入口二级页：动作 chips + 最好成绩卡（较上次变化 / 🔥 新纪录）+ 近 90 天 Canvas 折线；口径=最好一组/最大次数/最长秒 |
| 卡片折叠 | 点头部折叠/展开（折叠态「动作名 · N 组」+箭头旋转动画；有待填行的卡不折叠；新卡默认展开） |
| 时长单位 | 全链路**秒**（v8→v9 已迁移：durationMin 改名 durationSec、存量 ×60） |
| 删除 | 已保存组行尾垃圾桶图标 `Icons.Outlined.Delete` 32dp |
| 进度点 | 卡片头部 4dp 圆点，N 组亮 N 个（待填行空心） |

## 二、唯一待办：选择动作对话框改"左右两栏"（用户 2026-10-30 追加拍板）

> 现状代码：`TrainingScreen.kt` 的 `ExerciseSelectDialog`——**顶部横向 LazyRow 类别条 + "选择动作"标题**。
> 用户要求：类别**竖着放**、删标题。只改这一处，其余行为全部不动。

### 规格

1. **删除对话框标题**：`title = { Text("选择动作") }` 整行去掉；取消按钮保留。
2. **左右两栏布局**（对话框 text 区改为一个 `Row`）：
   - **左栏（类别，约 88dp 宽 + 浅灰分隔）**：竖向列表，从上到下 `全部 / 腿 / 背 / 胸 / 肩 / 臂 / 腹`；每项一整行可点（高约 40dp、14sp），**选中项主题色文字 + 淡底高亮**，未选中 `onSurfaceVariant` 灰；默认选中"全部"。
   - **右栏（动作列表，`Modifier.weight(1f)`）**：显示 `selectedGroup` 类别下的动作（"全部"= 全部动作）；动作行样式同现状（只显示动作名，15sp）；类别为空时显示灰字"该部位还没有动作"。
3. 过滤逻辑不变：`selectedGroup in it.muscleTags`（多标签动作在其每个类别下出现）。
4. 底部「＋ 新建动作」整行宽入口位置不变（在右栏列表之下或对话框底部均可，保持现有高度与点击区）。
5. 选中动作 → 关闭 → 回训练页出卡片的流程不变；新建动作对话框（名称 + 多选部位 chips + 重名提示）不动。

## 三、待办二：历史页显示训练摘要（用户 2026-10-30 拍板，方案 A）

> 现状：`HistoryScreen` 每日卡片只有饮食营养条 + 💪/😴 标记，训练内容完全不可见。
> 方案 A = 历史卡片加"训练摘要行"，外加修正历史列表的数据源边界问题。

### 改动内容

1. **每日卡片加训练摘要行**（`DailyTotalCard`）：营养条下方加一行，如「🏋️ 深蹲 4 组 · 引体 3 组」：
   - 有训练记录的日子显示；无记录的日子不显示（保持卡片干净）；
   - 摘要 = 该日 `training_entries` 按动作聚合（动作名 + 组数，`组数 DESC` 排序），与今日页训练入口行同款文案格式（「X N 组 · Y M 组」）；
   - 数据查询：DAO 按日聚合训练（或复用 `observeByDate` 思路加一个 `Flow<Map<date, List<ExerciseCountOfDay>>>`，一次查历史范围避免逐日 N+1 查询，实现自选但勿在 LazyColumn 每个卡片里单独发查询）。
2. **历史列表数据源改并集**：现状 `dailyTotals`（饮食汇总）驱动列表——**只练了没吃（没记饮食）的训练日在历史页隐身**。改为"有饮食 ∨ 有训练记录"的日子都出卡片（无饮食那天营养行为空或显示"—"，训练摘要行照常显示）；排序、分页习惯不变。
3. **点卡片进单日**：现有行为（回"今日"页看该日）不动；训练卡片随日期解耦已自然显示该日训练，验收时顺带回归确认即可。
4. 文案与视觉：摘要行 12sp、`onSurfaceVariant`，加 🏋️ 前缀与 💪 训练日标签形成呼应；不引入新颜色。

## 四、待办三：编辑动作（名称 + 部位标签）（用户 2026-10-30 拍板）

> 现状：`exercises` 动作创建后**无任何编辑入口**——名字打错、部位选错只能重建，错误动作留在列表碍眼。数据库层也缺 update 语句。

### 改动内容

1. **入口**：动作选择对话框（待办一改造后的右栏动作列表）每行**右侧加 ✎ 小图标**（`Icons.Outlined.Edit`，**16dp 图标**，灰 `onSurfaceVariant`；点行身仍是选动作，点 ✎ 才是编辑）。图标再小一档以弱化存在感——它是低频编辑操作，视觉重量必须低于"选动作"本身；点击热区仍保持 ≥32dp（`IconButton` 包裹小图标，图标小、热区不小，防误触不减可用性）。
2. **编辑对话框**：复用新建动作界面样式——名称输入框 + 部位多选 chips（同款选中态淡底+描边），标题「编辑动作」，确认按钮「保存」。
   - 可改：**名称**（重名校验同新建）+ **部位标签**（至少选一个）。
   - **不可改 recordType**：已由历史数据定型、看板口径依赖；界面不显示该字段。
3. **数据层**：`ExerciseDao` 加 update 方法（`@Update` 或按字段 update 语句），Repository/ViewModel 加对应方法；**无数据库结构改动、无迁移**。
4. **对历史记录的影响（关键约束，验收必查）**：`training_entries` 只存 `exerciseId`，动作改名/换标签后——
   - 今日页卡片、历史摘要、看板 chips 与曲线**全部自动显示新名称**（引用式，所见即所得），**不改动任何 training_entries 行**；
   - 部位标签变更后，选择器的类别归类立即跟随新标签。
5. **明确不做**：删除动作（牵扯看板/历史对已删动作的空引用，暂不做）；编辑训练记录的成绩数字（保持只能🗑删除重记）。
